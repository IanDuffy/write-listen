====================================================================
SHARED NAMES (both use exactly these strings)
====================================================================
- `/api/live/start` answer: a new boolean field, `"earpiece_view"`.
- Fates: `"sent" | "held" | "dropped"`.
- Reasons for "dropped" (`director.FATE_REASONS`):
  - `"not_here"`: the page isn't in a state to send (detail says which condition)
  - `"stale_after_start"`: offer, pitch, interest or start after the chapter started
  - `"explained"`: an offer once the guide had said what it does, or already offered
  - `"listener_spoke"`: a "now" note, and the listener spoke after the look was asked
  - `"gap"`: within `min_gap_secs` of the last whisper
  - `"replaced"`: a newer look's note replaced it before it was sent
  - `"forgotten"`: a rest, a wake or a new session cleared it (`dirForget`)
  - `"down"`: the earpiece went down while the note waited
  - `"ended"`: the conversation ended. Panel only, never posted.
- Plan change rule, used by both the panel and the history. Compare a look's plan with the previous look in the same conversation that had a plan. Match items by text, lowercased with whitespace collapsed.
  - An item that wasn't there before: change "new".
  - An item whose state differs: change = its new state ("done", "dropped" or "open").
  - An unchanged item: null.
  - Items that are gone go in `removed`.
  - The first look has every change null and `removed` empty.
- Time shown everywhere: m:ss since the conversation started, plus local clock HH:MM:SS.

A4. Timeline builder (voice/gpt_live/earpiece_history.py; pure file reading, no model)
- `conversations(folder: Path) -> list[dict]` and `timeline(folder: Path, session: str) -> dict`.
- `plan_changes(prev, plan) -> (plan_with_change, removed)` follows the shared rule.
- `timeline()` answer:
  `{"lid", "session", "started", "ended", "director": {"looks", "notes", "sent", "dropped", "held", "errors", "cost_usd"}, "items": [...]}`
  Items come in file order. Every item has `"t"` (iso), `"clock"` ("HH:MM:SS"), `"secs"` (int since the first row) and `"kind"`:
  - `{"kind": "line", "who": "guide"|"listener", "text"}`
  - `{"kind": "note", "text", "whisper": bool, "look": int|null}`: a "page" row. `whisper` is true when `director.whisper_in(text)` matches. `look` is the id of the look whose note equals that whisper's note (the latest such look before the row).
  - `{"kind": "tool", "name"}`
  - `{"kind": "session", "live_id"}`: a "session" row, meaning a new GPT-Live session.
  - `{"kind": "look", "id", "trigger", "speaking", "ms", "asked_secs": secs - round(ms/1000), "cost_usd", "error": str|null, "read", "plan": [{"item", "state", "change"}], "removed": [str], "next", "changed", "note", "note_kind": the row's kind, "about", "fate", "delivered", "reply"}`
- The fate fields on a look:
  - `fate`: `{"fate": "sent"|"dropped"|"held", "reason", "detail", "held_secs": float|null, "t", "clock", "secs", "inferred": bool}` or null. Built from the "director_fate" rows with the same id: the final row wins, and a "held" row fills `held_secs` = (final secs - held secs) or comes from `held_ms`.
  - With no fate rows (older conversations) but a matching whisper note after the look: `{"fate": "sent", "inferred": true, ...}` at that note's time.
  - With neither: null. The page shows that as "no fate recorded (the page had moved on or closed)".
  - `delivered`: `{"t", "clock", "secs"}` of the matched whisper note row, else null.
  - `reply`: the first "guide" row after the delivered row, as `{"t", "clock", "secs", "after_secs": its secs - delivered secs, "text"}`, else null. Label it as the line's end ("ended +N s"), since rows are written when a line ends.
- "director_fate", "event" and any other `who` are not items of their own.

B1. The hook in page/live.js (feeds the panel and posts fates; must not change any decision)
- `L.dirEvents = []` in L, kept across conversations and capped at 500.
- `dirEmit(type, fields)`:
  - builds `ev = {type, at: Date.now(), secs: L.convAt ? Math.round((at - L.convAt) / 100) / 10 : null, session: L.session, ...fields}`
  - pushes it onto `L.dirEvents`
  - then `try { window.Earpiece && Earpiece.event(ev) } catch (e) {}`
  - It never throws, never awaits, and never reads anything back from Earpiece.
- Emit points:
  - `connect()`, after `if (!resume) L.convAt = now();`: `dirEmit("conversation", {handoff: !!L.handoffOpen})`. For a resume that came up: `dirEmit("session", {reason: resume})`.
  - `directorAsk`, after `mark("direct-ask")`: `dirEmit("ask", {id, trigger, speaking, silence_ms, last_who, page})`, the same values as the request body.
  - `directorGot`, first line: `dirEmit("look", {id: got && got.id, got})`. This fires for error answers too. If a new whisper replaces a pending `D.next`, call `dirFate(oldNext, "dropped", "replaced")` before replacing it. The new `D.next` also carries `id: got.id`.
  - `directorFailed(why, id)`: pass the look id from the `directorAsk` callbacks, then `dirEmit("fail", {id, why, fails: D.fails})`. When it goes down: if `D.next`, call `dirFate(D.next, "dropped", "down")` first, then `dirEmit("down", {})`.
  - `directorDeliver`:
    - "hold": `if (!n.heldAt) { n.heldAt = t; dirFate(n, "held"); }` (once per note, not every tick)
    - "drop": `dirFate(n, "dropped", directorWhy(n, t, st, C), detail)`. The detail is `dirHereWhy()` for not_here, or `"<s> s after the last"` for gap.
    - "send": build the text, call `dirFate(n, "sent", null, null, {text})`, then `instruct(text)` as now.
    - `st` is the same object that is passed to `directorVerdict`. Hoist it into a const.
  - `dirForget(why)`: if `D.next`, call `dirFate(D.next, "dropped", "forgotten", why)`. Then `dirEmit("forget", {why})`. The callers pass `"new session: " + resume`, `"rest"` and `"wake"`.
  - `newConversation()`: if the old `L.dir.next` is pending, `dirEmit("fate", {id, fate: "dropped", reason: "ended", note, kind, about})`. Panel only, not posted.
  - Lines. The 200 ms loop's guide line, next to `directorLine(false)`: `dirEmit("line", {who: "guide", text, began: L.lineAt || t})`. The listener line: `{who: "listener", text, began: L.inStart || L.inAt}`. A typed line (around line 2626): `{who: "listener", text, typed: true, began: now()}`.
  - `instruct(text)`: `dirEmit("note", {text})`.
- `dirFate(n, fate, reason = null, detail = null, extra = {})`:
  - builds `body = {session: L.session, id: n.id, fate, reason, detail: detail && String(detail).slice(0, 200), secs, held_ms: n.heldAt && fate !== "held" ? t - n.heldAt : null}`
  - unless `reason === "ended"`, and if `L.session && n.id != null`: `quietPost("/api/live/direct/fate", body)`
  - then `dirEmit("fate", {...body, note: n.note, kind: n.kind, about: n.about, ...extra})`
  - Fates are posted whenever the earpiece is on, with or without the panel, so the admin history is complete for every tester. This is fire-and-forget and changes nothing.
- New pure functions, exported on `window.Live` next to `directorVerdict`:
  - `directorWhy(n, t, st, C) -> reason | null`. It mirrors `directorVerdict`'s order: not_here → stale_after_start → explained → listener_spoke (kind now) → gap. It returns null exactly when the verdict isn't "drop".
  - `dirHereWhy() -> ""` when `dirHere()`, else the first failing condition, in `dirHere`'s order. Labels: "off", "phase <phase>", "no session", "channel closed", "muted", "waiting on the guide", "handing back", "debrief", "held", "reading started", "chapter offered", "stepping back", "reply wait", "after a sound wake", "tool call in flight", "guide not yet spoken". Do not refactor `dirHere`, `directorVerdict` or anything else that decides.
- Loading:
  - In `connect()`, after a fresh `/api/live/start`: `if (got.earpiece_view) loadEarpiece(); else if (window.Earpiece) Earpiece.remove();`
  - `loadEarpiece()`: if `L.earpieceLoaded`, return. Otherwise set it true and append `<script src="/earpiece.js" async>` to document.head. On error, set `L.earpieceLoaded = false`. This works in the gate document too: the handover injects live.js there.
  - Nothing reads the flag from `S`.
